Agent Middleground

A neutral room for agents, run by open code. Two sides bring their data to a room under a public rule sheet. The middle ground looks at both together, writes a signed confirmation token for each side, in fixed shapes only, and wipes the data. Nothing is stored. Everyone can see the exact code that is running.

Rule sheets it runs

Each kind of meeting has a public rule sheet: what each side brings, which values stay private, and what each side may learn, in fixed shapes. Every confirmation token names the fingerprint of the sheet that wrote it. The built-in sheets are in rules.js. A business can also bring a sheet of its own, as plain data, with no change here.

How the connection is kept safe

  
An agent talks to this middle ground the same way a browser talks to any "https" website. Nobody on the internet in between can read or change what is sent, in either direction.

  

    
1. Proof of address
The middle ground holds a certificate for its web address, issued by a trusted certificate authority. The agent checks it first. A fake copy at another address cannot pass this check.

    
2. A fresh secret
The agent and the middle ground agree on a secret key for this one conversation. Nobody listening can work it out, and it is thrown away afterwards.

    
3. Everything encrypted
Every request and every answer is encrypted with that key. If anything is changed on the way, the receiver notices and drops it.

  

  


  
For agents and businesses

  
Any agent or business system can meet here with plain web requests: JSON in, JSON out. The starter code in starters/ makes each one a single call.

  

    
AddressWho uses itWhat it does

    
POST /api/joinA business or officeJoins once and gets a key. A business that issues certificate tokens names its open stamp key.

    
GET /api/rulesAnyoneThe rule sheets this middle ground runs, each with its fingerprint.

    
POST /api/openEither sideOpens a room with a built-in rule sheet, or one the business brings, and the data for its side. Names the fingerprint of the sheet it accepts.

    
GET /api/roomsAnyoneThe rooms waiting: public fields, what each asks for, and its rule sheet.

    
POST /api/bringThe other sideComes into a room with its data and certificate tokens, naming the sheet it accepts. Gets its confirmation token; the data is wiped.

    
POST /api/pickupThe side that opened the roomCollects its confirmation token. A pool room's office gets counts so far.

    
POST /api/deliverA business, after a meetingSends a certificate token it signed (an offer letter) to the key the person shared.

    
POST /api/mailboxA person's agentCollects the certificate tokens sent to it.

    
POST /api/checkAnyone shown a tokenChecks a token this middle ground made: the stamp, the time, a single use, and the showing of a carried token.

    
GET /api/key?id=AnyoneThe open key for a key id named in a token, so the token can be checked by itself.

    
GET /api/status, /api/statement, /api/auditAnyoneWhat is running and the live counts; the host's stamped statement of its code; the latest audit token.

  


  
Host your own

  
Any basic cloud server can run this, with nothing to install but Node. Fork the repo, say who you are in host.js, and start it. The repo's README has the steps, including https and the public deploy.

  
git clone https://github.com/tonymcodes/Agent-Middleground-Protocol
cd Agent-Middleground-Protocol
npm start
